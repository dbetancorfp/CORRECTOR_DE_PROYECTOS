Día 1 — Fundamentos del lenguaje y OOP

Base sólida del lenguaje: ámbito de variables, contexto de ejecución, estructuras de datos y programación orientada a objetos con prototipos y mixins.

var / let / const

var tiene ámbito de función y sufre hoisting. let tiene ámbito de bloque. const es una referencia inmutable — el objeto al que apunta sí puede mutarse.

this y pérdida de ámbito

El valor de this depende de cómo se invoca la función, no de dónde se define. Las arrow functions capturan el this léxico y no crean el suyo propio.

// bind — fija this una vez
new Bar(this.write.bind(this))

// arrow — captura léxico
new Bar(() => this.write())

Array funcional

a.filter(v => v % 2 === 0)
a.map(v => v * v)
a.reduce((acc, v) => acc + v)
a.find(v => v > 3)

class y prototipos

class es azúcar sintáctico sobre el sistema de prototipos. La cadena es: instancia → Clase.prototype → Object.prototype → null.

Mixins — composición horizontal

const Add = base =>
  class extends base { add() {} }

class Customer extends
  inherit().withMixins(Add, Update, Remove, Get) {}

class User extends
  inherit().withMixins(Get) {}

Día 2 — Asincronía, azúcar sintáctico y módulos

Sintaxis moderna ES2015+, modelo de ejecución asíncrona y sistema de módulos nativo.

Truthy / Falsy

Valores falsy: 0, '', false, null, undefined, NaN. Usar siempre === y !==.

Ojo: [] y {} son truthy.

Rest / Spread / Destructuring

function sum(...values) { ... }

const c = [...a, ...b]
const r = { ...foo, ...bar }

const [a, b, ...rest] = arr
const { id, name } = obj

Closures y disposables

function events(node, event, cb) {
  node.addEventListener(event, cb)
  return () =>
    node.removeEventListener(event, cb)
}

const dispose = events(btn, 'click', fn)
dispose() // cleanup garantizado

Event loop

Call stack → Microtasks (Promises) → Macrotasks (setTimeout). Las microtasks se vacían completamente antes de procesar el siguiente macrotask.

Async / Await

async function main(id) {
  try {
    const customer = await getCustomer(id)
    const invoices = await getInvoices(customer.id)
  } catch (err) {
    console.log(err)
  }
}

Módulos ES + import dinámico

// Estático
import { fn } from './module.js'

// Dinámico — lazy loading
const m = await import('./page.js')
m.default()

Día 3 — DOM y Web Components

Árbol DOM, APIs nativas de manipulación y los tres pilares de Web Components: Custom Elements, Shadow DOM y Templates.

Jerarquía DOM

HTMLElement ↓ Element ↓ Node ←— Text, Comment ↓ EventTarget ↓ Object → null

Custom Elements + ciclo de vida

class MyEl extends HTMLElement {
  static observedAttributes = ['color']

  connectedCallback()    { /* setup  */ }
  disconnectedCallback() { /* cleanup */ }
  attributeChangedCallback(name, old, val) {}
}
customElements.define('my-el', MyEl)

Shadow DOM

constructor() {
  super()
  const shadow = this.attachShadow({ mode: 'open' })
  // mode 'open'   → accesible vía .shadowRoot
  // mode 'closed' → no accesible desde fuera
}

Constructable Stylesheets

import styles from './c.css' with { type: 'css' }

constructor() {
  super()
  const shadow = this.attachShadow({ mode: 'open' })
  shadow.adoptedStyleSheets = [styles]
}

Campos privados + patrón disposables

class MyEl extends HTMLElement {
  #disposables = []

  connectedCallback() {
    this.#disposables.push(
      events(this, 'click', this.#onClick)
    )
  }

  disconnectedCallback() {
    this.#disposables.forEach(d => d())
    this.#disposables = []
  }
}

Delegación + composedPath

#handlerClick(ev) {
  const node = ev.composedPath()
    .find(n => n.dataset && 'index' in n.dataset)
  if (node) {
    const { index } = node.dataset
  }
}

Día 4 — Web Components avanzados y Performance

Arquitectura de componentes desacoplados mediante CustomEvent y técnicas de optimización de rendimiento web.

CustomEvent — comunicación desacoplada

this.dispatchEvent(new CustomEvent('ns:action', {
  bubbles: true,   // sube por el DOM
  composed: true,  // cruza Shadow DOM
  detail: structuredClone(data)
}))

Arquitectura de capas

Presentacional: recibe datos, renderiza, sin lógica de negocio.

Contenedor: gestiona estado, delega rendering en hijos.

Servicio: lógica pura, sin dependencia del DOM.

Core Web Vitals

LCP: tiempo hasta el elemento más grande visible.

INP: tiempo de respuesta ante interacciones.

CLS: desplazamiento acumulado del layout.

Optimización de imágenes

<!-- Imagen LCP -->
<img src="hero.webp"
     fetchpriority="high"
     loading="eager"
     decoding="async"
     width="1200" height="600">

<!-- Imágenes secundarias -->
<img src="item.webp"
     loading="lazy"
     decoding="async"
     width="400" height="300">

Cache-Control para assets estáticos

/* Assets con hash — inmutables */
Cache-Control: public, max-age=31536000, immutable

/* HTML — siempre revalidar */
Cache-Control: no-cache

/* API — nunca cachear */
Cache-Control: no-store

Formatos de imagen

<picture>
  <source type="image/avif" srcset="...">
  <source type="image/webp" srcset="...">
  <img src="fallback.jpg" ...>
</picture>

AVIF ~45-55% mejor que JPEG. WebP ~25-35%. Fallback progresivo con <picture>.
