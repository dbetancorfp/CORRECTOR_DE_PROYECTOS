Arquitectura técnica

Esta aplicación se construye mediante un pipeline RAG Spec-Driven Development: los prototipos HTML anotados con números de boceto y una conversación de requisitos se convierten, a través de 6 agentes Claude, en código backend + frontend completamente trazable y testado.

El principio sketchNumber

Cada elemento interactivo de los prototipos recibe un atributo data-element-id="N". Ese entero — el sketchNumber — es la clave foránea universal que vincula todos los artefactos del pipeline:

Boceto (#N) → UI Spec { sketchNumber: N, type, states, interactions } → Functional Spec { sketchNumber: N, behavior, businessRules, acceptanceCriteria } → Use Case UC-N: pasos referenciando #N → Test (rojo) describe('Element #N', () => { it('should...') }) → Código (verde) class ElementN extends HTMLElement { ... } → HTML <button data-element-id="N">
Invariante: ningún elemento puede aparecer en una fase posterior si no estaba numerado en el boceto. Zero ambigüedad por diseño.

Pipeline: 6 agentes especializados

1
Diseñador Front ✓ implementado Lee los 11 bocetos HTML anotados y boceto-metadata.json. Extrae tipo, props, estados, interacciones, accesibilidad y validaciones por sketchNumber. Ejecutar con /designer-front en Claude Code. → corrector/03-generated-artifacts/ui-spec.json · phase: ui-spec
2
Analista de Negocio Lee la conversación con el cliente, boceto-elements.md y la UI Spec (del RAG). Genera comportamiento, reglas de negocio y criterios de aceptación por sketchNumber. → functional-spec.json · phase: func-spec
🚪
GATE HUMANO — Reconciliación Verifica que cada sketchNumber del boceto tenga su func-spec y viceversa. Sin elementos huérfanos. Requiere aprobación manual antes de continuar. → reconciliation.json { valid: true }
3
Arquitecto de Requisitos Con las specs validadas genera los casos de uso, el DDL de PostgreSQL y los contratos de API. → use-cases.md · schema.sql · api-contracts · phase: use-case
4
Ingeniero TDD Deriva tests de los acceptanceCriteria. Cada describe() referencia un sketchNumber. Los tests se escriben antes del código y deben fallar. → tests/*.test.js (rojo ✗) · phase: test-red
5
Implementador Lee los tests rojos y los contratos de API. Genera solo el código suficiente para que los tests pasen. Backend Node.js + Frontend Web Components. → src/ (backend + frontend) · phase: code
6
Revisor / QA (opcional) Valida calidad del código, convenciones OO y ausencia de dead code. Sugiere refactorizaciones. → refactor suggestions

Frontend: Web Components nativos

Cada componente UI es un Custom Element nativo cargado directamente como ES Module. No hay bundler, no hay transpilación, no hay framework. El template engine es lit-html standalone.

Anatomía de un componente

// corrector-rubrica-cell.js
import { html, render } from 'lit-html';

export class CorrectorRubricaCell extends HTMLElement {

  connectedCallback() {
    this.attachShadow({ mode: 'open' });
    this._disposables = [];                       // patrón disposables
    this._render();

    const onSelect = e => this._handleSelect(e);
    this.shadowRoot.addEventListener('click', onSelect);
    this._disposables.push(
      () => this.shadowRoot.removeEventListener('click', onSelect)
    );
  }

  disconnectedCallback() {
    this._disposables.forEach(fn => fn());        // limpieza garantizada
    this._disposables = [];
  }

  _handleSelect() {
    this.dispatchEvent(new CustomEvent('corrector:grade-selected', {
      bubbles: true,                              // sube por el DOM
      composed: true,                             // cruza Shadow DOM
      detail: { level: this.getAttribute('level'), value: Number(this.getAttribute('value')) },
    }));
  }

  _render() {
    const level    = this.getAttribute('level') ?? '';
    const value    = this.getAttribute('value') ?? '0';
    const selected = this.hasAttribute('selected');   // ?attr binding
    const grades   = JSON.parse(this.getAttribute('grades') ?? '[]');

    render(html`
      <td
        .title=${`Nivel: ${level}`}              <!-- .prop binding -->
        @click=${() => this._handleSelect()}     <!-- @event binding -->
        ?aria-selected=${selected}               <!-- ?attr binding -->
      >
        ${value}
        <ul>${grades.map(g => html`<li>${g}</li>`)}</ul>   <!-- list -->
      </td>
    `, this.shadowRoot);
  }
}

customElements.define('corrector-rubrica-cell', CorrectorRubricaCell);

Reglas del sistema de componentes

ReglaDetalle
NombrePrefijo corrector-*, guión obligatorio, registrado con customElements.define
Shadow DOMattachShadow({ mode: 'open' }) siempre en connectedCallback
Renderizadohtml + render de lit-html. Nunca innerHTML directo.
Bindings.prop (propiedad), @event (listener), ?attr (atributo booleano), repeat o map (listas)
LifecycleconnectedCallback: setup + render + suscribir. disconnectedCallback: vaciar disposables.
DisposablesCada addEventListener / observer / intervalo añade su cleanup a this._disposables[]
ComunicaciónCustomEvent con bubbles: true y composed: true. Los eventos cruzan Shadow DOM boundaries.
Módulosexport class en fichero propio. Cargado con <script type="module">. Sin bundler.
SOLIDUn fichero = una responsabilidad. Extensión via atributos/slots. Eventos desacoplan emisor y receptor.

Workflow CLI (planificado)

# ── Agente 1: UI Spec (implementado) ─────────────────────────────
# Opción A — Claude Code (incluido en plan Pro)
/designer-front

# Opción B — CLI programático (requiere ANTHROPIC_API_KEY en .env)
npm run agent:designer-front
# equivale a:
node cli/index.js run-agent designer-front --feature-id corrector-v1

# ── Agente 2: Functional Spec ─────────────────────────────────────
/business-analyst

# ── Gate humano: Reconciliación ───────────────────────────────────
node cli/index.js reconcile --feature-id "corrector-v1"

# ── Agente 3: Casos de uso + SQL + contratos API ──────────────────
node cli/index.js run-agent requirement-architect --feature-id "corrector-v1"

# ── Agente 4: Tests TDD (deben fallar) ───────────────────────────
node cli/index.js run-agent tdd-engineer --feature-id "corrector-v1"
npm test                                   # RED ✗

# ── Agente 5: Implementación ──────────────────────────────────────
node cli/index.js run-agent implementer --feature-id "corrector-v1"
npm test                                   # GREEN ✅

# ── Publicar documentación ────────────────────────────────────────
git push main                              # → GitHub Pages (CI/CD)
