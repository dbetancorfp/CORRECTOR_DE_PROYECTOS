UC-01 Login y autenticación
ActorProfesor / Admin
PrecondicionesEl usuario no está autenticado. El sistema tiene al menos una cuenta en la BD.
Elementos
#1 Campo usuario #2 Campo contraseña #3 Botón Acceder #4 Logo #5 Navbar con Salir
Flujo principal
  1. El usuario accede a la pantalla de login (/).
  2. Introduce su nombre de usuario en el campo #1 (formato Consejería, e.g. dbetqui; el admin usa el literal Admin).
  3. Introduce su contraseña en el campo #2 (siempre enmascarada).
  4. Pulsa el botón Acceder (#3).
  5. El sistema valida las credenciales contra la BD.
  6. Si las credenciales son correctas y la contraseña no es la predeterminada 12345678, el sistema crea una sesión y redirige a /admin (admin) o /profesor (profesor/tutor).
  7. La barra de navegación (#5) muestra el nombre de usuario autenticado. El botón Salir destruye la sesión sin confirmación y redirige a /.
Flujos alternativos
  • A1 — Credenciales inválidas: Se muestra Credenciales incorrectas. El contador de intentos fallidos aumenta en 1.
  • A2 — Tercer intento fallido: La cuenta queda bloqueada (locked = true). Se muestra Póngase en contacto con el Administrador. Si es el admin, mensaje diferente y requiere intervención en BD.
  • A3 — Primer acceso (contraseña predeterminada): Si la contraseña es 12345678, aparecen dos campos adicionales en la misma pantalla para nueva contraseña y confirmación. Si coinciden y no son 12345678, se actualiza la BD y se redirige.
  • A4 — Cuenta bloqueada: El usuario no puede hacer login. Solo el admin puede desbloquearlo (UC-05, A3).
Postcondiciones
  • El usuario tiene una sesión activa y está en su pantalla de inicio según el rol.
  • failed_login_attempts se resetea a 0 tras un login exitoso.
Criterios de aceptación
  • Cuando las credenciales son válidas, el usuario es redirigido a /admin (admin) o /profesor (profesor/tutor)
  • Enviar un usuario vacío muestra un error de campo obligatorio
  • Los caracteres del campo #2 siempre están enmascarados
  • Cuando la contraseña enviada es 12345678, aparecen dos campos adicionales en la misma pantalla
  • Cuando nueva contraseña y confirmación no coinciden, se muestra un error y el flujo se repite
  • Establecer la nueva contraseña como 12345678 es rechazado con un error de validación
  • Tras 3 intentos fallidos consecutivos la cuenta queda bloqueada y se muestra Póngase en contacto con el Administrador
  • Al pulsar Salir (#5), la sesión se destruye y el usuario es redirigido a / sin diálogo de confirmación
UC-02 Gestión de Legislaciones
ActorAdmin
PrecondicionesAdmin autenticado en /admin/legislacion.
Elementos
#6 Tabs admin #7 Campo siglas #8 Año inicio #9 Año fin #10 Botón Guardar #81 Botón Nuevo #82 Tabla legislaciones #83 Editar fila #84 Borrar fila
Flujo principal — Crear
  1. El admin pulsa Nuevo (#81); el formulario inline (#7, #8, #9) se limpia.
  2. Introduce la abreviatura (#7: 2–10 letras mayúsculas, única en el sistema), el año de inicio (#8) y el año de fin (#9: debe ser exactamente inicio + 1).
  3. Pulsa Guardar (#10). El sistema valida, realiza un INSERT y refresca la tabla #82 desde la BD.
  4. El formulario retiene los valores introducidos (no se limpia tras guardar).
Flujo principal — Editar
  1. El admin pulsa el icono de editar (#83) en una fila; el formulario inline se rellena con los valores actuales de esa fila.
  2. El admin modifica los campos y pulsa Guardar (#10). El sistema realiza un UPDATE y refresca la tabla #82.
Flujos alternativos
  • A1 — Siglas duplicadas: El guardado es bloqueado con un error de restricción única.
  • A2 — Año fin ≠ inicio + 1: El guardado es bloqueado con error de validación.
  • A3 — Borrado bloqueado: Si la legislación tiene ciclos asociados, se muestra un aviso bloqueante y no se elimina.
Criterios de aceptación
  • Enviar una abreviatura duplicada muestra un error de restricción única y bloquea el guardado
  • Una abreviatura con minúsculas o fuera del rango 2–10 caracteres es rechazada
  • Cuando año_fin ≠ año_inicio + 1, el guardado es bloqueado
  • Tras guardar, los campos del formulario retienen sus valores
  • El icono de editar (#83) rellena el formulario inline; no se abre modal
  • Una legislación con ciclos asociados no puede ser eliminada; se muestra un aviso bloqueante
UC-03 Gestión de Ciclos
ActorAdmin
PrecondicionesAdmin autenticado en /admin/ciclos.
Elementos
#11 Tab Ciclos #12 Botón Nuevo + modal #13 Tabla ciclos #14 Editar inline #15 Borrar fila
Flujo principal — Crear
  1. El admin pulsa Nuevo (#12); se abre un modal con exactamente dos campos: nombre y legislación (select).
  2. El admin introduce el nombre y selecciona una legislación. Guarda.
  3. El sistema valida, realiza un INSERT y refresca la tabla #13.
Flujos alternativos
  • A1 — Nombre duplicado bajo la misma legislación: Error de restricción única; guardado bloqueado.
  • A2 — Legislación no seleccionada: Error de campo obligatorio.
  • A3 — Borrado bloqueado: Si el ciclo tiene módulos, se muestra un aviso bloqueante.
Criterios de aceptación
  • Pulsar Nuevo abre un modal con exactamente los campos: nombre y legislación (select)
  • Guardar un nombre ya existente bajo la misma legislación muestra un error de restricción única
  • El icono de editar activa la edición inline en la fila; no se abre modal
  • Borrar un ciclo con módulos asociados muestra un aviso bloqueante y no elimina
  • Cuando no existen ciclos, se muestra un mensaje de estado vacío en la tabla #13
UC-04 Gestión de Módulos
ActorAdmin
PrecondicionesAdmin autenticado en /admin/modulos. Existen al menos una legislación y un ciclo.
Elementos
#16 Tab Módulos #17 Botón Nuevo + modal #18 Tabla módulos #19 Columna legislación #20 Columna ciclo #21 Editar inline #22 Borrar fila
Flujo principal — Crear
  1. El admin pulsa Nuevo (#17); se abre un modal con exactamente 5 campos: nombre, siglas, legislación (select UI-filter), horas_semanales (número), ciclo (select).
  2. Al seleccionar una legislación, el select de ciclo se filtra para mostrar solo los ciclos de esa legislación. La legislación no se almacena en el módulo.
  3. El admin completa los campos y guarda. La tabla #18 se refresca. La columna #19 muestra la legislación derivada del ciclo.
Flujos alternativos
  • A1 — Siglas duplicadas bajo la misma legislación: Error de restricción única.
  • A2 — Borrado bloqueado: Si el módulo tiene proyectos asociados, aviso bloqueante.
Criterios de aceptación
  • El modal tiene exactamente 5 campos: nombre, siglas, legislación (select), horas_semanales, ciclo (select)
  • Seleccionar una legislación filtra el select de ciclo para mostrar solo los ciclos de esa legislación
  • La edición inline no abre modal; los 4 campos (nombre, siglas, horas_semanales, ciclo) son editables en la fila
  • Al cambiar el ciclo en edición inline, la columna legislación (#19) se actualiza automáticamente
  • Un módulo con proyectos asociados muestra un aviso bloqueante al intentar borrarlo
UC-05 Gestión de Profesorado
ActorAdmin
PrecondicionesAdmin autenticado en /admin/profesorado.
Elementos
#23 Tab Profesorado #24 Botón Nuevo + modal #25 Tabla profesores #26 Columna ciclos #27 Columna módulos #28 Editar inline + desbloqueo #29 Borrar fila
Flujo principal — Crear
  1. El admin pulsa Nuevo (#24); se abre un modal con exactamente 4 campos: username, nombre completo, ciclo(s) (multi-select), módulo(s) (multi-select).
  2. El admin completa los campos. Un profesor puede tener módulos de diferentes ciclos.
  3. El admin guarda. El sistema inserta con contraseña predeterminada 12345678 y refresca la tabla #25.
Flujo principal — Editar / Desbloquear cuenta
  1. El admin pulsa el icono de editar (#28). La fila entra en modo edición inline: campos editables son username, nombre_completo, ciclos, módulos. La contraseña no es editable en este modo.
  2. El admin guarda. Si el profesor tenía la cuenta bloqueada, el guardado resetea failed_login_attempts a 0 y cambia locked a false.
Flujos alternativos
  • A1 — Username duplicado: Error de restricción única; guardado bloqueado.
  • A2 — Borrado bloqueado: Si tiene módulos asignados o correcciones guardadas, aviso bloqueante.
Criterios de aceptación
  • El modal tiene exactamente 4 campos: username, nombre_completo, ciclos (multi-select), módulos (multi-select)
  • Un profesor que no ha cambiado su contraseña muestra 12345678 en la columna de contraseña; si la cambió muestra ********
  • En modo edición inline, el campo contraseña no se muestra
  • Guardar el registro de un profesor bloqueado desbloquea la cuenta y resetea el contador de intentos
  • Un profesor con múltiples ciclos muestra los nombres separados por coma en la columna #26
  • Un profesor con múltiples módulos muestra las siglas separadas por coma en la columna #27
UC-06 Gestión de Alumnos
ActorProfesor
PrecondicionesProfesor autenticado en /profesor/gestionar/alumnos.
Elementos
#31 Tab Alumnos #32 Filtro código #33 Filtro ciclo #34 Filtro legislación #35 Botón Nuevo #36 Tabla alumnos #37 Col. ciclo #38 Col. legislación #39 Editar inline #40 Borrar fila #41 Subir lista
Flujo principal — Crear alumno
  1. El profesor pulsa Nuevo (#35); se abre un modal con 4 campos: nombre_completo, identificador (código anónimo), ciclo (select), legislación (select UI-filter).
  2. El sistema inserta el identificador y ciclo en la tabla alumnos, y el nombre_completo en la tabla segura de privacidad alumno_nombres.
  3. La tabla #36 se refresca mostrando solo el identificador anónimo (no el nombre_completo).
Flujo principal — Subida masiva
  1. El profesor pulsa Subir lista (#41) y selecciona un fichero YAML, CSV o JSON.
  2. El sistema parsea el fichero fila a fila. Las filas válidas se insertan; las inválidas se omiten.
  3. Al finalizar, se muestra un informe con las filas omitidas y el motivo de cada rechazo.
  4. La tabla #36 se refresca.
Flujos alternativos
  • A1 — Identificador duplicado: Error de restricción única; guardado bloqueado.
  • A2 — Borrado bloqueado: Si el alumno tiene notas o asignaciones, pop-up con dependencias listadas.
  • A3 — Fichero no parseable: Error de parseo; nada importado.
  • A4 — Formato no soportado: Error; solo YAML, CSV y JSON aceptados.
Postcondición clave
  • Los nombres reales de los alumnos NO son visibles en la tabla #36 (solo el código anónimo).
  • La tabla alumno_nombres contiene los nombres reales vinculados por identificador.
Criterios de aceptación (selección)
  • El modal tiene exactamente 4 campos; la legislación actúa como UI-filter para el select de ciclo
  • Tras guardar, el nuevo alumno aparece en #36 solo con el identificador anónimo
  • nombre_completo se almacena en la tabla segura y no se muestra en #36
  • Escribir en #32, #33 o #34 actualiza la tabla #36 tras 300ms sin pulsar ningún botón
  • Las filas válidas se importan aunque otras filas del mismo fichero sean inválidas
  • Tras la importación, se muestra un informe con las filas omitidas y el motivo
UC-07 Gestión de Proyectos
ActorProfesor
PrecondicionesProfesor autenticado en /profesor/gestionar/proyectos. Existen alumnos y módulos.
Elementos
#42 Selector módulo activo #43–#45 Filtros #46 Botón Nuevo + modal #47 Tabla proyectos #48 Col. alumnado #49 Col. DEPRECATED #50 Editar inline #51 Borrar fila
Flujo principal — Crear proyecto
  1. El profesor selecciona un módulo activo mediante #42. La tabla #47 se recarga.
  2. Pulsa Nuevo (#46); se abre un modal con 4 campos: nombre, año_académico (select con start_years de las Legislaciones), ciclo (prelleno con el ciclo del módulo activo, modificable), alumnos (multi-select: 1–3 alumnos del ciclo seleccionado, no asignados en el mismo año).
  3. El proyecto queda vinculado al módulo activo.
Flujo principal — Editar proyecto
  1. El profesor pulsa editar (#50). Todos los campos son editables inline.
  2. Si se elimina un alumno con correcciones, aparece un aviso antes de guardar. Si confirma, el alumno y sus correcciones se eliminan en cascada.
Flujos alternativos
  • A1 — Sin alumnos / más de 3: Error de validación; guardado bloqueado.
  • A2 — Borrado bloqueado: Un proyecto con correcciones guardadas no puede eliminarse.
  • A3 — Columna #49: La columna "Añadir alumnado" (deprecated) no se renderiza en la tabla.
Criterios de aceptación (selección)
  • Solo los módulos asignados al profesor autenticado aparecen en el selector #42
  • El multi-select de alumnos muestra solo alumnos del ciclo seleccionado no ya asignados en el mismo año_académico
  • Seleccionar 0 o más de 3 alumnos bloquea el guardado con un error de validación
  • La columna "Añadir alumnado" (deprecated, #49) no se renderiza en la tabla de proyectos
  • Al guardar con un alumno eliminado que tiene correcciones, aparece un aviso listando los afectados e informando que sus correcciones serán eliminadas
  • Un proyecto con correcciones guardadas no puede eliminarse; se muestra un aviso bloqueante
UC-08 Gestión de Rúbrica
ActorProfesor
PrecondicionesProfesor autenticado en /profesor/gestionar/rubrica. Existen módulos asignados al profesor.
Elementos
#52 Tab Rúbrica #53 Filtro módulo #54 Filtro año #55 Nuevo ítem #56 Grid rúbrica #57 Nombre ítem #58 Excelente #59 Muy bien #60 Bien #61 Regular #62 Mal (0, fijo) #63 Subir rúbrica #64 Puntuación máxima #90 Borrar ítem
Flujo principal — Seleccionar módulo y editar rúbrica
  1. El profesor escribe en el filtro #53; se muestra una lista de módulos asignados. Selecciona uno y los ítems de la rúbrica se cargan en el grid #56.
  2. Los campos del grid son siempre visibles y editables sin doble click (si la rúbrica no está congelada). Cada campo se auto-guarda en la BD al perder el foco (blur).
  3. Valores deben respetar orden descendente: Excelente > Muy bien > Bien > Regular > 0 (Mal fijo = 0.00).
  4. El campo #64 muestra la suma de todos los valores Excelente; en rojo si ≠ 10.00.
Flujos alternativos
  • A1 — Rúbrica congelada: Si existe alguna corrección para la rúbrica del módulo, todos los campos (#56) son de solo lectura y los botones #55, #63, #90 muestran avisos bloqueantes.
  • A2 — Rúbrica inválida (suma ≠ 10.00): El campo #64 se muestra en rojo. La pantalla de corrección (UC-09) queda bloqueada para este módulo.
  • A3 — Subida desde fichero (#63): Si existe rúbrica previa sin correcciones, se pide confirmación de reemplazo total. Bloqueado si existen correcciones.
Postcondición clave
  • Un módulo tiene exactamente una rúbrica compartida por todos sus proyectos.
  • La suma de todos los valores Excelente debe ser exactamente 10.00 para que la rúbrica sea válida.
Criterios de aceptación (selección)
  • Los campos del grid son siempre visibles y no requieren doble click para editar (salvo rúbrica congelada)
  • Cambiar un valor de Excelente y perder el foco auto-guarda en la BD
  • La celda Mal siempre muestra 0.00 y no es editable
  • Cuando la suma es 10.00, #64 se muestra con estilo normal; cuando ≠ 10.00, en rojo
  • Si existe alguna corrección para la rúbrica del módulo, pulsar Nuevo (#55) muestra un aviso bloqueante
  • Tras borrar un ítem (#90), #64 se recalcula inmediatamente
UC-09 Corrección de Proyecto
ActorProfesor
PrecondicionesProfesor autenticado en la pantalla de corrección. Existe al menos un proyecto con rúbrica válida (suma Excelente = 10.00).
Elementos
#65 Filtro año #66 Filtro ciclo #67 Filtro módulo #68 Select proyecto #69 Grid corrección #70 Nombre ítem (read-only) #71 Excelente #72 Muy bien #73 Bien #74 Regular #75 Mal #76 Puntuación total #77 Checkbox grupo #78 Checkbox alumno 1 #79 Checkbox alumno 2 #80 Checkbox alumno 3
Flujo principal — Corrección en modo grupo
  1. Los filtros #65 (año, por defecto el actual), #66 (ciclo), #67 (módulo, solo los asignados al profesor) acotan la lista de proyectos en el select #68.
  2. El profesor selecciona un proyecto en #68. El grid #69 muestra el mensaje "Elige una opción para empezar a corregir". La puntuación #76 muestra 0. Todos los checkboxes (#77–#80) empiezan desmarcados.
  3. El profesor marca el checkbox Grupo (#77). Los checkboxes individuales #78–#80 quedan deshabilitados. El grid #69 carga los ítems con las notas previamente guardadas.
  4. El profesor hace click en la celda del nivel deseado para cada ítem. La selección se guarda asíncronamente para todos los alumnos del proyecto. La puntuación #76 se actualiza en tiempo real.
Flujo principal — Corrección individual
  1. El profesor marca el checkbox de un alumno individual (#78, #79 o #80). El grid carga los ítems con las notas previamente guardadas para ese alumno.
  2. El profesor corrige ítem a ítem. Cada selección se guarda asíncronamente solo para ese alumno.
Flujos alternativos
  • A1 — Sin checkbox activo al hacer click en celda: Aparece una notificación deslizante en la parte derecha. El click no se guarda.
  • A2 — Rúbrica inválida: Si la rúbrica del módulo tiene suma Excelente ≠ 10.00, se muestra un error en lugar del grid. El profesor debe ir a la pestaña Rúbrica y corregirla.
  • A3 — Re-corrección: El profesor puede cambiar un nivel ya seleccionado en cualquier momento; el nuevo valor sobrescribe sin confirmación.
  • A4 — #79 / #80 ocultos: El checkbox del alumno 2 (#79) no se renderiza si el proyecto tiene solo 1 alumno. El checkbox del alumno 3 (#80) no se renderiza si el proyecto tiene menos de 3 alumnos.
Criterios de aceptación (selección)
  • El filtro #65 muestra el año académico actual por defecto
  • El filtro #67 solo muestra los módulos asignados al profesor autenticado
  • Después de seleccionar un proyecto en #68, el grid muestra el mensaje "Elige una opción para empezar a corregir"
  • Marcar #77 deshabilita y desmarca #78, #79, #80 y muestra el grid con los ítems
  • Con #77 marcado, hacer click en una celda guarda la nota para TODOS los alumnos del proyecto
  • La etiqueta de cada checkbox individual (#78–#80) muestra el nombre_completo del alumno
  • Si no hay ningún checkbox activo al hacer click en una celda, aparece una notificación deslizante y el click no se guarda
  • Si la rúbrica es inválida (suma ≠ 10.00), se muestra un error en lugar del grid
UC-10 Visualización e impresión de Notas
ActorProfesor / Tutor
PrecondicionesEl usuario está autenticado en /profesor/notas. El rol Tutor accede únicamente a esta pantalla.
Elementos
#30 Botón Imprimir (Tutor) #85 Select año #86 Select ciclo #87 Select módulo #88 Botón Descargar PDF #89 Tabla previsualización
Flujo principal — Seleccionar filtros en cascada
  1. El select #85 muestra los años académicos disponibles (valores año_académico distintos de los proyectos existentes).
  2. Al seleccionar un año en #85, el select #86 se recarga con los ciclos activos para ese año; los selects #87 y #88 se resetean.
  3. Al seleccionar un ciclo en #86, el select #87 se recarga con los módulos asignados al profesor autenticado para ese ciclo; #88 permanece deshabilitado.
  4. Al seleccionar un módulo en #87, la tabla de previsualización #89 se carga. El botón #88 se habilita.
Flujo principal — Previsualización y descarga PDF
  1. La tabla #89 muestra columnas: Proyecto, Nombre alumno, Niveles evaluados, Nota final.
  2. Nota final: media ponderada de todos los módulos del ciclo: Σ (nota_módulo_i × (horas_módulo_i / Σ horas_módulos_ciclo)). Módulos sin corrección contribuyen 0.
  3. Los alumnos con correcciones incompletas aparecen con sus datos parciales y un indicador incompleto.
  4. Si algún módulo del ciclo no tiene correcciones, se muestra un aviso listando los módulos pendientes.
  5. El profesor pulsa Descargar PDF (#88). Se descarga un fichero PDF (no diálogo de impresión del navegador).
Flujos alternativos
  • A1 — #88 deshabilitado: El botón está deshabilitado mientras cualquiera de #85, #86, #87 esté vacío.
  • A2 — Acceso del Tutor: El botón #30 en la landing del profesor es visible solo para rol Tutor y navega a /profesor/notas. Para el rol Profesor, #30 no se renderiza.
  • A3 — Acceso no autorizado del Tutor: Si el Tutor intenta navegar a cualquier ruta que no sea /profesor/notas, es redirigido a /profesor/notas.
Criterios de aceptación (selección)
  • El botón #30 se renderiza cuando el usuario autenticado tiene rol tutor; no se renderiza para el rol profesor
  • El select #86 está deshabilitado hasta que #85 tiene valor; el select #87 está deshabilitado hasta que #86 tiene valor
  • El botón #88 está deshabilitado mientras cualquiera de #85, #86, #87 esté vacío
  • nota_final es la media ponderada de todos los módulos del ciclo: cada módulo × (horas_módulo / Σ horas_módulos_ciclo)
  • Los módulos sin corrección contribuyen 0 a la nota_final
  • Los datos de la previsualización #89 coinciden con los datos del PDF descargado
  • Pulsar #88 descarga un fichero PDF (no diálogo de impresión del navegador)
  • Un usuario con rol Tutor que intenta acceder a una ruta distinta de /profesor/notas es redirigido a esa ruta
